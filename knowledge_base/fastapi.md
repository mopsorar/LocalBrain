# FastAPI в Python Backend

FastAPI помогает строить HTTP API на Python с явным описанием входных и выходных данных. Модели Pydantic проверяют структуру JSON, обязательные поля и ограничения значений. Например, пустую строку с вопросом лучше отклонять на границе API, а не передавать её в бизнес-логику. Схема OpenAPI формируется из объявленных типов и помогает клиентам понимать контракт сервиса.

Обработчик запроса должен координировать работу компонентов, а не содержать весь алгоритм приложения. Чтение документов, создание эмбеддингов и запись в хранилище удобно держать в переиспользуемых функциях. Тогда один алгоритм можно вызывать из скрипта индексации и из HTTP-обработчика. Результат операции должен сообщать, сколько документов и фрагментов действительно обработано.

Асинхронная функция не делает любую вызываемую библиотеку неблокирующей. Синхронный HTTP-клиент, файловые операции и длительные вычисления могут остановить event loop. Для сетевого ввода-вывода выбирают асинхронный клиент, а подходящую синхронную работу передают в рабочий поток. Общие клиенты создают на время жизни приложения и освобождают при остановке.

Ошибки клиента и ошибки инфраструктуры имеют разный смысл. Некорректные входные данные требуют ответа о валидации, отсутствие внешнего локального сервиса — контролируемой ошибки доступности. Не следует возвращать успешный статус с выдуманным результатом. В журнал достаточно записывать техническую причину сбоя, идентификатор запроса и имя операции, не раскрывая содержимое приватных документов.
