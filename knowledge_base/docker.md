# Docker для локального backend-проекта

Образ Docker содержит приложение и зависимости, необходимые для его запуска. Контейнер является экземпляром образа с собственным окружением процессов и файловой системой. Разделение помогает воспроизводить запуск, но не устраняет необходимость учитывать доступную оперативную память и процессор. На небольшом компьютере несколько тяжёлых сервисов могут конкурировать за одни и те же ресурсы.

Dockerfile обычно сначала устанавливает зависимости из зафиксированного списка, а затем копирует исходный код. Такой порядок позволяет повторно использовать слой с библиотеками, если меняется только приложение. В контекст сборки не должны попадать виртуальное окружение, секреты, локальная база, реальные документы и скачанные модели. Для исключения этих файлов служит отдельный список правил сборки.

Данные, которые должны пережить удаление контейнера, хранят в именованном томе или в специально подключённом каталоге. Запись базы только во внутреннюю файловую систему контейнера создаёт риск потери данных при пересоздании. Путь к постоянному хранилищу передают через конфигурацию. Резервная копия и проверка восстановления остаются отдельными задачами даже при использовании тома.

Сетевой адрес зависит от места выполнения процесса. Внутри контейнера localhost указывает на этот контейнер, а не на соседний сервис. В общей сети Compose сервисы обычно доступны по своим именам. Для публикации порта на машине разработчика желательно ограничивать интерфейс прослушивания, если доступ из внешней сети не требуется. Секреты не записывают в образ и не публикуют в репозитории.
